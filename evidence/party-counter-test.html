공유 카운터에 상태 조건을 걸지 않은 이유

카운터 UPDATE에 상태 조건을 걸면, 완료 직후 도착한 기여가 0행으로 버려져 멤버 기여분 합계와 카운터가 어긋납니다.

두 트랜잭션이 끼어드는 순서를 실제 PostgreSQL에서 재현하고, 지금 코드와 상태 조건을 건 UPDATE를 같은 순서로 비교했습니다.

상황

파티 목표는 4,000이고, 멤버 4명의 기준값은 모두 1,000입니다.

A · B · C가 1,000씩 기여해 카운터는 3,000인 상태에서 시작합니다.

A가 카운터를 올리기 직전에 D가 완료를 가져가는 순간이 문제입니다.

A는 이미 퀘스트를 ACTIVE로 읽고 자기 멤버 행을 고쳤기 때문에, 이 기여는 카운터에도 들어가야 합니다.

비교한 두 UPDATE

카운터를 올리는 문장만 바꾸고, 나머지 절차는 같습니다.

완료 여부는 두 경우 모두 아래의 조건부 UPDATE 한 곳에서만 정합니다.

지금 코드

update PartyQuest q
   set q.currentVal = q.currentVal + :delta
 where q.partyQuestId = :partyQuestId

트레이드오프 A

update game_service.party_quests
   set current_val = current_val + :delta
 where party_quest_id = :id
   and status = 'ACTIVE'

완료 선점 (두 경우 공통)

update PartyQuest q set q.status = :completed
 where q.partyQuestId = :partyQuestId
   and q.status = :active
   and q.expiredAt > :at
   and q.currentVal >= q.targetVal

끼어들기 재현

A 트랜잭션 안에서 D 트랜잭션을 다른 스레드로 끝까지 실행해, 끼어드는 순서를 매번 같게 고정했습니다.

두 트랜잭션이 잡는 행이 겹치지 않아 서로 기다리지 않습니다.

A는 자기 멤버 행만, D는 자기 멤버 행과 카운터 행을 갱신하기 때문입니다.

Outcome aOutcome = tx.execute(s -> {
    // 1. A는 퀘스트를 ACTIVE로 읽고 자기 멤버 행에 +500을 반영한다
    assertThat(partyQuestJpa.findActiveByUserId(a, ACTIVE, at(10, 30))).isNotEmpty();
    int delta = applyToMember(questId, a, 2_500, at(10, 30));

    // 2. A가 카운터를 올리기 전에 D가 다른 트랜잭션에서 완료를 선점하고 커밋한다
    dOutcome[0] = other.submit(() -> contribute(tx, counter, questId, d, 2_000, at(10, 3))).get();

    // 3. A가 카운터를 올리고 완료 선점을 시도한다
    int rows = counter.add(questId, delta);
    int claimed = partyQuestJpa.claimCompletion(questId, at(10, 30), ACTIVE, COMPLETED);
    return new Outcome(rows, claimed);
});

단언

상태 조건이 없으면 합계가 맞는다

Race race = runRace(current());

assertThat(race.d().claimed()).isEqualTo(1);
assertThat(race.a().counterRows()).isEqualTo(1);
assertThat(race.a().claimed()).isEqualTo(0);

PartyQuest after = readQuest(race.questId());
assertThat(after.getStatus()).isEqualTo(COMPLETED);
assertThat(after.getCurrentVal()).isEqualTo(4_500);
assertThat(sumOfContributions(race.questId()))
        .isEqualTo(after.getCurrentVal());

상태 조건을 걸면 합계가 어긋난다

Race race = runRace(guarded());

assertThat(race.d().claimed()).isEqualTo(1);
assertThat(race.a().counterRows()).isEqualTo(0);

PartyQuest after = readQuest(race.questId());
assertThat(after.getCurrentVal()).isEqualTo(4_000);
assertThat(sumOfContributions(race.questId()))
        .isEqualTo(4_500);

왼쪽은 지금 코드가 맞다는 단언입니다.

A의 +500이 카운터에 들어가고, A의 완료 선점은 0행이라 보상도 한 번만 나갑니다.

오른쪽은 트레이드오프 A가 실제로 어긋난다는 단언입니다.

이 테스트가 통과한다는 것은 A의 +500이 버려지는 것을 재현했다는 뜻입니다.

결과

두 테스트 모두 통과했습니다.

같은 끼어들기에서 지금 코드는 카운터와 멤버 기여분 합계가 4,500으로 같았고, 상태 조건을 건 UPDATE는 4,000과 4,500으로 어긋났습니다.
